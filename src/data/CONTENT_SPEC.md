# iller8 Content Spec — how to write phrases, words & options

**Read this before adding or editing any lesson content.** It exists so that
content (including content written by subagents) stays *pristine, consistent, and
in‑line with what's already here*. Hand a subagent this file + the lesson it's
expanding and it should be able to match the house style exactly.

If you only remember three things:
1. **Teach the language, not a phrasebook.** Every phrase, cue, note and option
   should help the learner actually *understand and produce* Serbian.
2. **Cues are situations, never definitions or riddles.** Options are minimal
   pairs, never gameable.
3. **Keep it natural and modern** — the kind of Serbian you'd really text or say.

---

## 1. Who this is for (voice & audience)

The learner is an adult English speaker learning **conversational, modern Serbian**
to talk to his **half‑Serbian girlfriend**, his **Bosnian best friend**, and a
**colleague**. He wants to sound natural, not like a textbook. He has **beginner
Russian and Turkish** — so loanword origins from those (and others) are genuinely
interesting to him.

Tone of the content: warm, concrete, a little playful, never academic. Write `en`
and `notes` the way a fluent friend would explain it.

---

## 2. The data model

Lessons live in `src/data/lessons/NN-name.json`, registered in
`src/data/lessons/index.ts`. Shape (see `Lesson`/`Phrase` in `src/store/types.ts`):

```jsonc
{
  "id": "texting",
  "title":       { "sr_latin": "...", "sr_cyrillic": "...", "en": "..." },
  "description": { "sr_latin": "...", "en": "..." },
  "order": 3,
  "prerequisites": [],
  "phraseGroups": [
    { "id": "casual-greetings", "theme": "Casual Greetings",
      "phrases": [ /* Phrase objects */ ] }
  ]
}
```

### Phrase fields
| field | required | what it's for / rules |
|---|---|---|
| `id` | ✅ | unique kebab slug, stable forever. Prefix by lesson where helpful (`tx-…`, `rx-…`, `ef-…`). **Never reuse an id across lessons** (it collides in progress + meta). |
| `sr_latin` / `sr_cyrillic` | ✅ | the Serbian, both scripts, kept in exact 1:1 transliteration. This is what audio, tiles and typing use — keep it clean (see Abbreviations §7 for the one exception). |
| `en` | ✅ | natural English meaning. Not a literal gloss — what you'd actually say. `/` separates equally‑good options ("Hey / Hi / Bye"). |
| `context` | ✅ | the **situational cue** shown as the exercise prompt. See §4 — this is the most‑abused field. |
| `notes` | optional | concise post‑answer explanation. See §5. |
| `gloss_hint` | optional | short disambiguator shown after answering (e.g. `"to a woman"`, `"lit. 'my soul'"`). Keep `en` clean; put parentheticals here. |
| `wordRefs` | strongly encouraged | the content words this phrase is built from. Drives word‑readiness gating AND grammar‑stage tagging. See §8. |
| `variations` | optional | gender / formality / person variants. See §9. |
| `audio_cyrillic` | rare | TTS‑only override: makes the voice *speak* this while the clip stays keyed by `sr_latin`. Used for abbreviations (§7). |

## 3. The grammar PATH & difficulty (what "harder" means)

Content is sequenced by a grammar spine, not by topic. Each phrase is auto‑tagged
with a **stage** + **difficulty** in `src/data/phrase-meta.json` (generated by
`node scripts/tag-phrases.mjs` from `wordRefs`). Stages (`src/data/grammar-stages.ts`):

| stage | key | what it introduces |
|---|---|---|
| 0 | chunks | fixed expressions used whole (greetings, reactions, "volim te") |
| 1 | present | present‑tense verbs, `hoću/mogu/moram da…` |
| 2 | accusative | objects — "I want a coffee" (acc ending) |
| 3 | genitive | "there isn't…", `kod/iz/do`, possession |
| 4 | past‑future | past (agrees with gender) + future |
| 5 | dative | feelings/experiencer — `sviđa mi se`, `nedostaješ mi` |
| 6 | loc‑ins | "in town", "with you" |
| 7 | clitics | 2nd‑position clitic order ("si mi ga") |
| 8 | aspect | perfective vs imperfective, relative clauses, conditional |

**How stage is decided:** the tagger reads `wordRefs` — cases (`case`), verb forms
(`form`), clitics, etc. So *tag `wordRefs` well and the stage falls out correctly.*
A phrase's stage = the hardest feature it contains.

**When adding content, aim to fill the thin upper stages.** Current rough counts:
stage 0–2 are full (~130/90/110), **3–6 are thin (15/7/2/1), 7 ≈ 27, 8 ≈ 0**. New
content is most valuable at **stages 3–6 and 8** (genitive, past/future, dative,
loc/ins, aspect) — and should *build on* vocabulary already taught at lower stages
so it's reachable. Don't pile more stage‑0/1 chunks unless they're high‑value.

---

## 4. Writing `context` — the situational cue (most important rule)

`context` is shown as the **prompt** in context‑pick ("here's the situation — pick
the Serbian"). It must point at exactly one phrase. See memory `[[context-cues]]`.

**DO** — a concrete, second‑person *situation*, ≤ ~120 chars:
- ✅ "Your friend's flight got cancelled again — react to the bad news." (`rx-uzas`)
- ✅ "You're trying to find a friend in a crowd, or just tossing them a casual hello." (`gde-si`)
- ✅ "A friend apologizes for forgetting to call back — brush it off, it's fine." (`nema-veze`)

**DON'T:**
- ❌ a bare definition — "When something is terrible."
- ❌ a riddle / two actors — "Shouted at the birthday person; the crowd responds with this."
- ❌ leak the answer's **form or register** — never "say it in one word", "in two words", "(slang)", and never quote the English answer inside the cue.
- ❌ "Short for 'nema veze'…" (assumes the learner already knows the answer).

---

## 5. Writing `notes` — concise, and etymology‑aware

`notes` appears **after** answering. Keep it 1–2 sentences. Good `notes` cover one of:
grammar (a case/tense/gender point), usage, or **origin**.

**Etymology — call it out when the root is foreign and interesting** (the learner
knows some Russian & Turkish):
- ✅ "'Jok' comes from Turkish — short, punchy, very natural." (`08`)
- ✅ "'Kafa' (not Croatian 'kava') — domaća, Turkish‑style coffee, not espresso."
- ✅ "From Italian 'ciao'." (`ćao`)
- Worth flagging origins: **Turkish** (jok, bre, sokak, čaršija, džE…), **Russian/Church‑Slavonic**, **Italian/German/Greek**, **English** (tech/slang). Skip origin notes when the word is plain native Serbian.

**Bosnian vs Serbian — mention only SUBSTANTIAL differences** (the best friend is
Bosnian):
- ✅ worth it: a different word entirely, a Turkish‑flavoured Bosnian variant, a
  pronunciation/word that would mark you as Serbian vs Bosnian (e.g. `kafa`/`kahva`,
  `hleb`/`hljeb`, ijekavian `mlijeko` vs `mleko`).
- ❌ not worth it: trivial reductions like "'e' is just 'je'". Don't note those.

**Gender:** when a form changes for m/f speaker/listener, say so briefly ("'Gladna'
= hungry (feminine); 'gladan' for masculine.") and add a `variations` entry (§9).

> The exact, checkable version of all of this — length bounds, the `notes` ordering
> law, the `gloss_hint` closed vocabulary, the `wordRefs` completeness rules, and the
> per‑entry QA checklist — is in the **RIGID RULES appendix** at the end of this file.
> The appendix wins when there's any ambiguity.

---

## 6. Writing `en`

Natural, what you'd actually say. Lowercase only for genuine lowercase items
(`nvm`, `btw`). Use `/` for equally‑valid renderings. Don't cram register notes into
`en` — use `gloss_hint`.

---

## 7. Abbreviations (texting shorthand)

The learner is learning the **meaning**, not just how to shorten a phrase he already
knows. So **write the full form with the shorthand in parentheses**, and let the
voice speak the full form:

```json
{
  "id": "tx-jbg",
  "sr_latin": "Jebiga (jbg)",
  "sr_cyrillic": "Јебига (јбг)",
  "en": "Oh well / It is what it is",
  "context": "Plans fall through and there's nothing to be done — text the resigned 'oh well'.",
  "notes": "Texted 'jbg', short for 'jebiga'. As normalized as 'damn' — pure resigned acceptance.",
  "audio_cyrillic": "Јебига"
}
```

Rules: `sr_*` = `Full form (abbr)`; `audio_cyrillic` = the spoken **full form** (so the
clip says "jebiga", not "jebiga jbg"); `context` is a situation, never "short for X".
This makes the option set teach real words instead of being a letter‑matching game.

---

## 8. `wordRefs` — tag the content words

`wordRefs` lets the engine (a) gate a phrase until its words are met, and (b) compute
its grammar stage. Tag the **content** words (verbs, nouns, key pronouns/particles),
not every filler.

- Bare string for a lemma already neutral in the phrase: `"sutra"`, `"da-conj"`.
- Object form when the surface differs from the lemma — **carry the case/form**:
  ```json
  { "id": "kafa", "surface": "kafu", "surface_cyrillic": "кафу", "case": "acc" }
  { "id": "biti", "surface": "si",  "surface_cyrillic": "си",  "form": "2sg.pres" }
  { "id": "duša", "surface": "Dušo", "surface_cyrillic": "Душо", "case": "voc" }
  ```
- `case`: `nom|acc|gen|dat|loc|ins|voc`. `form`: `1sg.pres`, `past.f.sg`, `imp.2sg`,
  `3sg.pres.neg`, etc. **These tags decide the stage**, so get them right.
- The lemma id should exist (or be added) in `src/data/words/`. Unknown ids are
  dropped silently, so they won't gate — but they also won't teach the word.

After adding/altering `wordRefs`, run `node scripts/tag-phrases.mjs` to refresh
`phrase-meta.json`.

---

## 9. `variations`

For the same idea bent by gender / formality / person. Keep `sr_latin`,
`sr_cyrillic`, `en`, and a `gloss_hint` saying which variant it is:
```json
"variations": [
  { "sr_latin": "Jesi gladan?", "sr_cyrillic": "Јеси гладан?", "en": "Are you hungry?", "gloss_hint": "to a man" }
]
```
Bigger grammatical "bend this phrase" sets live in `src/data/phrase-families.json`
(the perspective drill) — use those for systematic tense/case/aspect transforms.

---

## 10. Multiple‑choice options must be minimal pairs

Options are generated (`src/engine/minimal-pair-distractors.ts` +
`src/data/confusables.json`); see memory `[[project-distractors-and-ramp]]`. The
content you write should make this work:

- **Every option shares the answer's core noun and differs on ONE axis** (verb
  meaning, person, tense, the noun's case ending). Never let one option be the only
  one mentioning the keyword.
- **No option may be *also correct*** for the prompt (the cardinal sin). When you
  add a phrase to a group, make sure it isn't a valid answer to a neighbour's cue.
- To curate options for a phrase, add entries to `src/data/confusables.json` (verb
  sets that share a frame; noun case forms) — keep verb meanings clearly distinct
  (no near‑synonyms that could both be right).

---

## 11. Workflow for adding content

1. Write the phrases into the right `phraseGroups` (or a new group/lesson). Follow
   §4–§9. Keep `id`s unique.
2. Tag `wordRefs` (§8); add any missing lemmas to `src/data/words/`.
3. `node scripts/tag-phrases.mjs` → refreshes stages/difficulty.
4. `npm run generate-audio -- --voice both` → makes clips for new `sr_latin`
   strings (and for `audio_cyrillic` overrides). Commit the new clips.
5. `npx tsc --noEmit && npm run build` → must pass; JSON must parse.
6. Commit + push to `main` (GH Pages auto‑deploys).

---

## 12. The "pristine" checklist (the bar to hit)

For every phrase ask:
- [ ] Is the Serbian natural, modern, and correctly transliterated both scripts?
- [ ] Is `en` what a person would actually say?
- [ ] Is `context` a concrete situation that points at THIS phrase, leaking nothing?
- [ ] Is `notes` one tight idea (grammar / usage / origin), and does it flag a
      Turkish/Russian/other origin or a real Bosnian difference if there is one?
- [ ] Are `wordRefs` tagged with correct `case`/`form` (so the stage is right)?
- [ ] Are gender/person variants captured in `variations`?
- [ ] Would this phrase, and its options, read as an *excellent example* a subagent
      should imitate?

### Don'ts
- No developer/coding/office jargon — ever (see `[[no-dev-phrases]]`).
- No riddle/definition/answer‑leaking cues (§4).
- No "say it in one word / (slang)" form hints in cues.
- No also‑correct distractors.
- Don't over‑note: skip trivial Bosnian differences and obvious etymologies.

---

### Exemplary phrases to imitate
- **notes ordering + etymology + Bosnian:** `tx-ajde-na-kafu`
- **wordRefs completeness:** any `ef-` frame in `11-everyday-frames.json`
- **context as a clean situation:** `rx-uzas`, `tx-de-si`, `gde-si-nestao`
- **abbreviation pattern:** `tx-jbg`
- **gender variation:** `tx-jesi-gladna`

Read those, then write to the same standard.

# APPENDIX — RIGID RULES (the mechanical law)

§1–§12 above are the philosophy. This appendix is the **checkable law**: exact
bounds and formats so two different writers produce near‑identical‑shaped output.
When in doubt, the appendix wins. Every rule here is mechanically verifiable, and
`scripts/lint-content.mjs` enforces the hard ones.

## R1. Field bounds & format (hard)

| field | length | format law |
|---|---|---|
| `en` | ≤ 60 chars, ≤ 8 words per alternative, ≤ 3 `/`‑alternatives | Sentence case. Terminal `.`/`!`/`?` **only if** the Serbian has one, and it must MATCH the Serbian's terminal mark (parity — the option engine blocks mixing `?` with non‑`?`). ` / ` separates equally‑valid renderings, ordered literal→idiomatic, all the **same grammatical shape** (all questions or all statements). No parentheticals — those go to `gloss_hint`. Lowercase only genuinely‑lowercase items (`nvm`, `btw`). |
| `context` | 60–120 chars (hard cap 120) | ONE second‑person situation, present tense ("You…/Your friend…/Tell your…/Ask your…"). **Ends with `.`** — never `?`. **Never starts with "When"** (that's a definition frame). Points at exactly this phrase; leaks no answer word / form / register. |
| `notes` | ≤ 220 chars, 1–2 sentences (never 3) | Sentence case, full sentences. Serbian words/forms in **single quotes** always; **no double quotes ever**. `=` for glosses (`'X' = meaning`). Em‑dash `—` for an appositive aside (hyphen only inside words). Ordered grammar → usage → origin/Bosnian (R3). |
| `gloss_hint` | ≤ 28 chars | lowercase fragment, **no surrounding parentheses** (the UI adds them), no terminal punctuation. Use the **closed vocabulary** (R2). |
| `wordRefs` | non‑empty for any teachable phrase | every non‑nominative noun carries `case`; every non‑lemma verb/adjective carries `form`; grammar‑bearing clitics tagged (R4). |

Micro‑templates:
- `en`: `Natural English` or `Literal / Idiomatic / Casual`
- `context`: `[2nd‑person trigger situation] — [speech‑act instruction].`
- `notes`: `'<sr word>' = <gloss>; <one grammar or usage fact>.[ <Origin/Bosnian flag.>]`

## R2. `gloss_hint` closed vocabulary (do NOT invent variants)

The UI renders it as `(value)` italic — store the bare fragment only.
- addressee gender: `to a man` · `to a woman`
- speaker gender: `said by a man` · `said by a woman`  *(never `male speaker`/`female speaker`)*
- literal gloss: `lit. 'my soul'`  *(always `lit.` + space + single‑quoted gloss; never `lit:`)*
- register: `very casual` · `slang` · `formal`
- alternative phrasing: `another way to say it`
- role: `the required response`

If a needed hint isn't here, prefer rephrasing to fit; only extend the vocabulary
via a spec edit (not ad‑hoc in a lesson).

## R3. `notes` taxonomy & ordering (rigid)

A note is **at most one** sentence from each bucket, **in this order**:
1. **Grammar** (default first): a case/tense/gender/clitic point.
   `'<sr form>' = <gloss> (<case/tense>).` or `Literally '<gloss>' — <structural note>.`
2. **Usage** (optional): when/how it's really used, register, frequency.
3. **Origin / Bosnian** (optional, **always last**): foreign root worth flagging
   (Turkish, Russian/Church‑Slavonic, Italian/German/Greek, English) OR a SUBSTANTIAL
   Bosnian difference (`kafa`/`kahva`, `hleb`/`hljeb`, ijekavian `mlijeko`/`mleko`).
   `'<word>' comes from <language>.` / `Bosnians say '<form>'.`

Forbidden in notes: restating the English translation as the whole note; trivial
Bosnian diffs ("'e' is just 'je'"); obvious etymologies on native words; meta
("great phrase to learn"). Gender point states the shown form's gender and gives the
other inline AND gets a `variations` entry (never prose‑only, never variation‑only).

## R4. `wordRefs` law (highest‑leverage — sets gating AND stage)

- **`wordRefs: []` is harmful, not neutral.** Empty ⇒ readiness forced to 1.0 (no
  gating, the words are never taught) AND the phrase falls to the heuristic tagger.
  Ship `[]` ONLY for a phrase with zero teachable lemmas (a bare loanword interjection
  like `Super!`). Otherwise tag at least the head word.
- **Bare string** only when surface == lemma and it's nominative/neutral (`"sutra"`,
  `"da-conj"`, `"baš"`).
- **Object form** otherwise, carrying `surface` + `surface_cyrillic` + (`case` OR `form`):
  - noun in any non‑nominative case → `case` (`nom|acc|gen|dat|loc|ins|voc`)
  - verb/adjective not in lemma form → `form` (`1sg.pres`, `past.m.sg`, `past.f.sg`,
    `imp.2sg`, `1pl.pres`, `3sg.pres.neg`, `1sg.fut`, `3sg.fut.clitic`, …; dot‑separated, lowercase)
- **Tag grammar‑bearing clitics** even though they're small: dative `mi-dat`/`ti-dat`,
  future `će`/`ću`, past auxiliaries — they set the stage.
- Every `id` must exist in `src/data/words/words.json`. If you reference a new lemma,
  DO NOT edit `words.json` from a lesson agent — **emit the new lemma id in your report**
  for the Wave‑4 pass to add. (Unknown ids are dropped silently: no gate, no teaching.)
- After any `wordRefs` change: `node scripts/tag-phrases.mjs`.

## R5. `variations` law

- Trigger: same idea bent by gender (speaker or listener), formality, or a single
  near‑equivalent rephrasing.
- Every variation MUST carry `gloss_hint` from R2 (`to a man`, `said by a woman`,
  `another way to say it`, `formal`, …). `en` matches the base unless meaning shifts.
- Variation surfaces are auto‑excluded from distractors, so they can never be marked
  wrong — keep them genuinely valid.

## R6. Per‑entry QA checklist (every item must be YES)

- [ ] `id` unchanged, unique, lesson‑prefixed kebab.
- [ ] `sr_latin` ⇄ `sr_cyrillic` exact 1:1 transliteration (abbreviation exception per §7 with matching `audio_cyrillic`). Not edited unless fixing a transliteration error (flag it).
- [ ] `en` obeys R1 (≤60 chars, ≤3 parallel slash‑alternatives, no parentheticals, punctuation parity).
- [ ] `context` obeys R1 (60–120 chars, one 2nd‑person situation, ends `.`, no "When" opener, no leak).
- [ ] `notes` present (target 100%), obeys R1+R3 (≤220 chars, single quotes only, grammar→usage→origin, flags origin/Bosnian when real, no translation‑restate).
- [ ] `gloss_hint` (if any) obeys R1+R2 (≤28 chars, no parens, closed vocabulary).
- [ ] `wordRefs` obeys R4 (non‑empty, case/form complete, clitics tagged, lemmas exist or are reported).
- [ ] Gender/formality/person variants captured in `variations`, each with a `gloss_hint`.
- [ ] No dev/coding/office jargon.
- [ ] No option‑collision: not a valid answer to a neighbour's `context` in the same group.

## R7. Distractor reality (so content stays option‑safe)

Minimal‑pair options only fire when the phrase's verb/noun is in
`src/data/confusables.json` (`distractors.json` is currently empty). Covered today:
verbs `hteti, moci, morati, trebati, voleti, piti, jesti, praviti, mrzeti, ici,
dolaziti, odlaziti, zvati, pisati, pitati`; nouns `kafa, voda, kuća, muzika, knjiga`.
Everything else tops up from the pool by parity (length/punctuation/word‑overlap).
**Therefore:** keep `en` and `sr` parity‑friendly (R1), and never let a phrase be an
also‑correct answer to a neighbour. Adding new confusable verb sets/noun cases is a
Wave‑4 / spec task, not a lesson‑agent task.

## R8. Cross‑file policy (decisions, so agents don't diverge)

- **No dev jargon, anywhere.** The `dev-friend-chat` group in `03-texting.json`
  (`tx-sta-kodiras`, `tx-radi-li-ti`, `tx-pukao-server`, `tx-bagovi`) is removed/rethemed
  by the texting agent. (The contrived work‑banter dev phrases were already removed.)
- **Near‑duplicate phrases across lessons are allowed** (e.g. `rx-jao`/`jao`,
  `tx-moram-da-idem`/`ef-moram-da-idem`) — they reinforce across topics and have
  distinct ids. Do NOT delete them; just make each pristine in its own file.
- **Shared files (`words.json`, `confusables.json`, `phrase-meta.json`) are touched only
  in Wave 0 / Wave 4.** Lesson agents are read‑only on them and write only their lesson.
